# shin-wallslice 1.2.0 — Save wallpapers to your server

Configure an optional output directory to add **Save to server** alongside
**Download ZIP**. Saves write the current completed PNGs with the same safe names,
selected devices, crop framing, dimensions, and OLEDify settings as the ZIP.
Choose flat `<safe-name>-<device-id>.png` filenames or device folders containing
`<device-id>/<safe-name>.png`. Browser downloads remain available.

Existing files are listed for explicit **Replace** or **Cancel** before any PNGs
from that save are written. Approval applies to the reviewed render, name, layout,
and file state; changed conflicts require renewed review. Unsafe destination
links/directories are rejected. Pending and partial-failure feedback identifies
which files were saved and which need recovery. Saved PNGs survive Start over,
job expiry, restart, and replacement with their destination mount retained.

Install/update: [README](https://github.com/jmdarling/shin-wallslice#get-started)
and [Unraid guide](https://github.com/jmdarling/shin-wallslice/blob/main/docs/unraid.md).
Image: `ghcr.io/jmdarling/shin-wallslice:1.2.0`, with aliases `:1`, `:1.2`, and
`:latest`. Exact older releases and their minor-series aliases are preserved.

Enable using partial JSON `{"outputDirectory":"/data/output"}` or environment
`SHIN_WALLSLICE_OUTPUT_DIRECTORY=/data/output`. This uses the existing persistent
`/data` mount; a separate host bind mount at `/data/output` is also supported.
Prepare only the dedicated output directory for UID/GID 1000 write/traverse
permission. Saving is disabled by default and requires no additional mount,
database, or service. The UI accepts no destination paths. Keep output separate
from temporary storage; nested output/scratch paths fail startup to protect files.

Compatibility: existing configuration/preferences work unchanged with saving
unset. Node.js 24, non-root runtime, Linux amd64/arm64, and memory/storage budgets
are retained. Back up saved outputs in addition to preferences/private settings.
To roll back to 1.1.0, remove the new `outputDirectory` JSON key and environment
setting, and retain the data/output mounts. Older versions cannot save more PNGs
but leave existing persistent files intact. Temporary jobs do not survive
replacement. Releases do not update running installations automatically.
