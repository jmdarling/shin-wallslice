# v1.5.0 — Preserve originals in ZIP downloads and server saves

Status: implemented

Include the unchanged uploaded image alongside generated wallpapers whenever a
user downloads a ZIP or saves to the server. Keep originals in a dedicated
`originals/` folder, named using the current wallpaper name and original format.

## Feature: Original image in every ZIP

Every ZIP contains one original image in addition to the selected device PNGs.
The original is the file received by shin-wallslice, before orientation
normalization, color conversion, cropping, resizing, or OLEDify.

### Acceptance criteria

- [x] Every successful ZIP download contains exactly one `originals/<safe-name>.<extension>` entry whose contents are byte-for-byte identical to the accepted upload, including any embedded metadata and orientation information. JPEG, PNG, and WebP uploads retain their original format; the extension matches that format.
- [x] The original uses the same current safe wallpaper name, normalization, and fallback as the generated outputs. For example, a JPEG upload named `photo.jpg` exported with wallpaper name `Dusk Ridges` includes `originals/Dusk Ridges.jpg`; it does not retain `photo` as its base name.
- [x] The `originals/` folder sits at the ZIP root regardless of **Organize into device folders**. With organization off, device PNGs remain `<safe-name>-<device-id>.png`; with it on, they remain `<device-id>/<safe-name>.png`. Include one original per ZIP, independently of the selected device count.
- [x] File selection, drag-and-drop, and clipboard image input all preserve the exact image bytes received by the application. For clipboard input, this means the received clipboard image file, without claiming to recover an earlier file from which it was copied.
- [x] Changes to the wallpaper name, device selection, crop positions, OLEDify, and repeated rendering never alter or discard the original for the current job. Generated previews and device PNGs continue to use the existing normalized processing behavior. Individual **Download PNG** actions retain their existing behavior.
- [x] A ZIP is not reported or returned as successfully complete if its original cannot be included. Existing current-render validation remains in force, and expired or superseded jobs cannot export another job's original or stale outputs.

## Feature: Original image in every server save

**Save to server** writes the same original entry and generated device files as
the equivalent ZIP, relative to the configured output directory. Originals follow
the existing on-demand saving, conflict review, and persistent-output behavior.

### Acceptance criteria

- [x] Every successful server save includes `originals/<safe-name>.<extension>` beneath the configured output directory, with identical path and bytes to the original entry in an equivalent ZIP. Create the folder when permitted, regardless of device-folder organization. Do not add a wallpaper wrapper folder.
- [x] Existing original files participate in the same conflict review as device PNGs. An original-only conflict is listed and requires explicit **Replace** before any files from that save are written; **Cancel** leaves all destination files unchanged. Changed save details or conflicts require fresh confirmation under the existing rules.
- [x] Save feedback includes the original's relative path in saved, conflicting, or failed-file lists as applicable. A missing original, unavailable directory, permission error, or storage failure cannot produce a complete-success result; partial saves accurately identify saved and unsaved files and allow retry.
- [x] Original writes retain the existing destination confinement and protections against symbolic links, directories, special files, hard links, and destination changes. Neither wallpaper names nor file extensions can redirect writes outside the configured output directory.
- [x] Saved originals survive Start over, job expiry, temporary cleanup, application restart, and container replacement when the output mount is retained. Later saves preserve unrelated files and older originals unless their exact target paths are explicitly approved for replacement. Server saving remains optional and occurs only through **Save to server**.

exports it. Explain the additional file, its unchanged contents, and its storage
and privacy implications in the existing user guidance.
