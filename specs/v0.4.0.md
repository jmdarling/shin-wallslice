# v0.4.0 — Browser-driven dark mode

Status: implemented

Add dark mode throughout shin-wallslice, deriving the application's mode from the user's browser color-scheme preference. Keep the current light appearance when the browser prefers light mode or provides no preference.

## Feature: Automatic light and dark appearance

Follow the browser's color-scheme preference on initial load and whenever it changes while the application is open. Apply a coordinated appearance to the Input, Processing, and Download pages, including Web Awesome components and native controls. Retain the application's green visual identity in both modes.

The browser preference is the source of truth: this version adds no manual theme toggle, saved theme preference, or runtime configuration override.

### Acceptance criteria

- [x] Opening or reloading the application with a dark browser color-scheme preference displays dark mode from the first visible application render, without a visible flash of the light theme.
- [x] Opening or reloading with a light browser preference, no expressed preference, or unavailable color-scheme preference detection displays the existing light appearance.
- [x] Changing the browser preference between light and dark updates the visible page immediately without reloading; navigating to another page continues to use the current preference.
- [x] Both modes consistently style page backgrounds, headers, panels, cards, image surrounds, text, borders, selected states, Web Awesome components, and native form controls across Input, Processing, and Download.
- [x] Text, controls, keyboard focus indicators, warnings, errors, progress indicators, and the OLEDify loading toast remain readable and distinguishable in both modes on desktop and narrow mobile screens. Normal text meets a contrast ratio of at least 4.5:1, large text at least 3:1, and essential control boundaries and focus indicators at least 3:1 against adjacent colors.
- [x] Theme changes preserve the current source image, page, selected devices, crop settings and positions, OLEDify settings, edited name, and download organization choice, and do not interrupt pending upload or processing work.
- [x] Source images, device previews, and downloaded PNG contents retain their image colors in either mode; changing the application mode does not apply image filters or alter cropping, OLEDify processing, or exported output.
- [x] Browser tests cover initial light and dark preferences, the light fallback, and live preference changes without losing current workflow state. Visual verification covers all three pages and their interaction and status states in both modes at desktop and narrow mobile sizes.
