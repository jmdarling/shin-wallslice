# shin-wallslice 1.3.1 — Unified OLEDify working toast

OLEDify now uses one nonblocking toast for AI cutoff tuning and preview/output
rendering. The toast covers threshold edits, switching OLEDify on or off,
automatically applied defaults or recommendations, and Retry. When tuning and
rendering overlap, the same toast shows both phases and stays visible until the
active work finishes. Late or superseded render responses cannot dismiss it early.

Local fallback explanations, completed recommendations (including off), manual
control protection, and failure/Retry feedback remain inline. Working messages
are no longer duplicated inline on Processing or Download. The toast follows
navigation and clears when work finishes or its workflow is discarded. A failed
phase ends its progress without hiding another phase that is still active.

The toast does not capture focus or block controls. Users can navigate, download,
and save current completed outputs while AI tuning runs; incomplete or superseded
renders remain protected from export. Manual changes still protect both OLEDify
settings. The 15%/32 candidate rule, local cutoff 16 fallback, bounded vision
search, crop framing, naming, and pixel transformation are unchanged.

## Install, update, and roll back

Install/update: [README](https://github.com/jmdarling/shin-wallslice#get-started)
and [Unraid guide](https://github.com/jmdarling/shin-wallslice/blob/main/docs/unraid.md).
Image: `ghcr.io/jmdarling/shin-wallslice:1.3.1`, with aliases `:1`, `:1.3`, and
`:latest`. Retain existing persistent data and optional output mounts when
recreating the container. Publication does not update installations automatically.

No runtime settings, environment overrides, or persistence formats changed.
Existing 1.3.0 configuration and preferences remain compatible, and rollback to
`ghcr.io/jmdarling/shin-wallslice:1.3.0` needs no configuration changes. Earlier
rollback targets retain the configuration-removal requirements documented for
1.3.0. AI remains optional and disabled by default. The runtime remains Node.js 24,
non-root, one container/process/port, with Linux amd64 and arm64 support.

## Verification and limits

The developer verified the running app and explicitly signed off. Local
`pnpm check` passed lint, formatting, explicit TypeScript, **130 server tests**,
**83 Chromium Lit tests**, builds, and distribution validation. Browser coverage
includes independent/overlapping tasks, switch/threshold/automatic triggers,
queued renders, Retry, failures, stale responses, job cleanup, protected manual
choices, export guards, and keyboard/focus/status semantics at 320, 390, and 1440px
in light/dark appearances.

[Real application captures and verification notes](../design/v1.3.1/README.md)
show AI-only, overlapping, render-only, and completed states. The isolated review
helper uses real Fastify/Sharp rendering with a delayed deterministic local mock
provider; it does not submit images externally or evaluate model judgment. No
new live-model evaluation, dedicated human screen-reader session, or real Unraid
hardware test was performed. AI recommendations remain best effort, with the
previously documented possibility of visible artifacts and lost detail.

Native image publication, exact digest, vulnerability findings, anonymous registry
verification, and permanent release evidence will be recorded after the release
workflow finishes.
