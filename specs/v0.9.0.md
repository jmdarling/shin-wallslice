# v0.9.0 — Complete visual user documentation

Status: implemented

Make the root README a complete, attractive, approachable guide to installing, operating, and maintaining shin-wallslice. Help a first-time user reach their first exported wallpaper without repository knowledge, while keeping detailed configuration and troubleshooting easy to find.

## Feature: A complete, user-first README

Rewrite the README around the user's journey: understand the app, choose an installation path, start it, produce wallpapers, and maintain the installation. The README itself contains the full user guide; images and runnable supporting examples may live alongside it in the repository.

### Acceptance criteria

- [x] The opening explains what shin-wallslice does, shows the result visually, and summarizes its main capabilities: device-specific crops, manual positioning, OLEDify, PNG/ZIP downloads, and optional AI naming and subject detection.
- [x] A linked table of contents and clear headings make installation, usage, configuration, AI, maintenance, troubleshooting, and developer instructions directly accessible. The recommended first-run path appears before exhaustive reference material.
- [x] Installation choices explain their prerequisites and who each path suits. Docker is the primary home-server path, with Docker run, Compose, manual Unraid setup, and local Node.js all covered.
- [x] The guide is self-contained for app-specific setup and operation. It does not require reading specs, source files, or earlier releases to understand necessary settings or complete the workflow. External links may supplement platform prerequisites.
- [x] Short explanatory paragraphs, numbered procedures, focused tables, and labeled code blocks make the guide scannable. Advanced details do not interrupt the basic first-run procedure.
- [x] The README describes current verified behavior, removes the stale v0.2.0 introduction, and does not present planned features, a published image, or a Community Apps listing as available.

Explain all user-facing capabilities and all supported runtime settings with practical examples. Preserve the useful technical detail in the current README while reorganizing it around user questions.

### Acceptance criteria

- [x] Download examples show actual individual filenames and ZIP layouts with device-folder organization enabled and disabled. They explain editable base names and normalization, Back, Start over, browser reload, shared installation preferences, and which information is never restored.

File selection order is explicit `--config`, `/config/config.json`, then repository-root `config/local.json`.
- [x] Configuration examples are complete valid JSON or explicitly labeled fragments. The guide includes a minimal non-AI setup, a read-only mounted partial JSON example, an environment-based example, and an explicit `--config` invocation. It explains relative-path resolution, restart requirements, validation failures, and that dotenv files are not automatically loaded.
- [x] AI setup explains a vision-capable OpenAI-compatible Chat Completions endpoint, API base URL versus appended request path, model selection, optional bearer authentication, and how a container reaches a service outside itself. The guide describes representation/request limits, best-effort recognition, pending entropy previews, manual-edit protections, no-subject and failure fallbacks, and independent Retry actions.
- [x] The guide explains browser-driven light/dark appearance, image and decoded-pixel limits, memory/storage budgets, temporary-job capacity and expiry, and the single-user/shared-preference model. It accurately states the current authentication/access boundary and gives a suitable trusted-network deployment baseline without implying built-in access controls.
