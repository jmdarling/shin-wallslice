# shin-wallslice 1.6.0 — Choose devices before uploading

Input now offers the same output-device choices as Processing. Selections carry
through upload and use the existing remembered preferences and first-use defaults.
The upload box appears above the choices on desktop and mobile.

Recommended source dimensions update immediately as devices change: the largest
selected output width × largest selected output height. The default phone and
11-inch tablet recommend **2420 × 2868 px**; all six presets recommend
**3840 × 2868 px**. These dimensions are guidance. Smaller images still work with
the existing upscaling warnings. An empty selection shows a prompt and permits
upload; Processing requires a device before continuing to Download.

This release also ships the previously unreleased v1.5.0 original-export feature.
Every ZIP and server save includes the unchanged uploaded JPEG, PNG, or WebP in
`originals/<safe-name>.<extension>`, regardless of folder organization. The name
matches the chosen wallpaper name. Original bytes and embedded metadata remain
intact; review originals before sharing. Original files participate in the usual
server-save conflict review and remain in persistent output storage until removed
explicitly. Individual device PNG downloads retain their existing behavior.

## Install, update, and roll back

Install/update: [README](https://github.com/jmdarling/shin-wallslice#get-started)
and [Unraid guide](https://github.com/jmdarling/shin-wallslice/blob/main/docs/unraid.md).
Image: `ghcr.io/jmdarling/shin-wallslice:1.6.0`, with aliases `:1`, `:1.6`, and
`:latest` after successful publication. Retain existing persistent data and
optional output mounts when recreating the container. Publishing a release does
not update installations automatically.

No new configuration, environment variables, or preference migration is required.
Allow for the additional retained original and archive contents in temporary and
output storage. Existing resource safeguards account for original retention.
Rollback to `ghcr.io/jmdarling/shin-wallslice:1.3.1` needs no configuration change,
but removes Input device selection/source guidance and automatic original export.
Previously saved original files remain on disk. Older rollback targets retain the
configuration-removal requirements documented for v1.3.0.

The runtime remains Node.js 24, non-root, one container/process/port, with Linux
amd64 and arm64 support. AI remains optional and disabled by default.

## Verification and limits

The developer tried the running application and signed off. Local `pnpm check`
passed lint, formatting, strict TypeScript, **139 server tests**, **92 Chromium
Lit tests**, production builds, and distribution validation. The layout follow-up
also passed the 11 focused Input/selection/responsive tests and real workflow
verification. [Input verification and captures](../design/v1.6.0/README.md) cover
1440px/320px light/dark layouts, keyboard/emulated-touch choices, preference
restoration, invalid-image retry, empty-selection upload, and smaller-source
warnings. [Original-export verification](../design/v1.5.0/README.md) covers exact
original bytes, ZIP/server layouts, conflict review, retention, and local images
for both container architectures.

No dedicated human screen-reader session, physical mobile, or fresh Unraid
hardware test was performed. AI behavior is unchanged and remains best effort.

Native release builds, exact digest, vulnerability findings, anonymous registry
verification, and permanent release evidence will be recorded after the release
workflow finishes. A passing vulnerability gate does not imply zero findings.
