# v0.2.0 — First wallpaper workflow

Status: implemented

Replace the scaffold placeholder with a complete single-image workflow: Input → Processing → Download. Use `ui.excalidraw` as a layout and interaction guide, with Lit and Web Awesome throughout.

This is a single-user application without accounts. AI-assisted cropping, AI name suggestions, custom-device creation, per-device crop-method selection, and a saved wallpaper library are deferred.

## Feature: Single wallpaper input

Accept one JPEG, PNG, or WebP through drag-and-drop, clipboard image paste, or a clickable file picker. A successfully accepted image opens Processing. Keep resource safeguards appropriate for a home NAS without imposing unnecessarily restrictive upload limits.

### Acceptance criteria

- [x] Each of the three input methods accepts a supported image and opens Processing with that image visible.
- [x] The workflow handles one source image at a time; submitting multiple images produces a clear instruction to choose one.
- [x] Unsupported formats, corrupt images, and failed uploads produce actionable errors and allow another attempt without reloading the application.
- [x] Image orientation metadata is respected consistently in previews, crop coordinates, and exports.
- [x] Ordinary 8K images, including 7680×4320 and 8192×4320, can complete the workflow with all six presets selected on a deployment with 4 GiB of available application memory.
- [x] Resource safeguards account for decoded image size and processing memory rather than imposing an arbitrary small file-size cap. Inputs that would exceed the supported memory budget are rejected clearly before exhausting memory; documentation explains any enforced limits and their rationale.

## Feature: Expandable bundled output devices

Define the initial presets in repository-managed JSON, with stable IDs, display names, and output pixel dimensions. Adding a preset may require a repository change and release, but must not require rewriting device-selection, preview, or export logic. User-editable device definitions and runtime configuration overrides for the catalog are outside this version.

Phones use portrait, laptops use landscape, and tablets use square outputs whose side equals the screen's longer native pixel dimension. Dimensions below are width × height.

| Device                        | Stable ID                      | Output pixels |
| ----------------------------- | ------------------------------ | ------------- |
| iPhone 18 Pro Max             | `iphone-18-pro-max`            | 1320×2868     |
| M5 iPad Pro 11-inch           | `m5-ipad-pro-11-inch`          | 2420×2420     |
| M5 iPad Pro 13-inch           | `m5-ipad-pro-13-inch`          | 2752×2752     |
| M1, 2020 MacBook Air          | `m1-2020-macbook-air`          | 2560×1600     |
| 14-inch, Nov 2024 MacBook Pro | `14-inch-nov-2024-macbook-pro` | 3024×1964     |
| Generic 16:9 4K               | `generic-16x9-4k`              | 3840×2160     |

Native dimensions are based on Apple's specifications for [iPhone 18 Pro Max](https://support.apple.com/en-euro/148591), [11-inch M5 iPad Pro](https://support.apple.com/en-ie/125406), [13-inch M5 iPad Pro](https://support.apple.com/en-gb/125407), [M1 MacBook Air](https://support.apple.com/en-us/111883), and [14-inch 2024 MacBook Pro](https://support.apple.com/en-asia/121552). Tablet square dimensions apply the agreed wallpaper-sizing rule rather than the native rectangular aspect ratio.

### Acceptance criteria

- [x] Processing lists all six presets with individual selection controls and shows a crop editor for each selected device.
- [x] On first use, only iPhone 18 Pro Max and M5 iPad Pro 11-inch are selected; subsequent wallpapers use remembered selections.
- [x] Any combination of devices can be selected, but proceeding to Download requires at least one selection.
- [x] Every exported image has exactly its preset's dimensions, without stretching or adding borders.
- [x] If the source crop lacks sufficient pixels, the app warns for that device and still permits upscaling to the exact output dimensions.
- [x] Adding a valid JSON preset with a unique ID, name, and dimensions makes it available through selection, previews, and downloads using the existing workflow.

## Feature: Global crop methods and manual positioning

Provide a global Smart choice and a visual anchor selector with top-left, top-right, bottom-left, bottom-right, and center positions. Smart uses entropy-based cropping for this version, such as Sharp's entropy strategy. Default to Smart on first use.

Each selected device uses the largest crop rectangle of its required aspect ratio that fits inside the source. Users may reposition that rectangle independently for each device by dragging it over the source preview. Crop dimensions are fixed for that source and aspect ratio; there is no zoom or crop resizing.

### Acceptance criteria

- [x] Smart computes an entropy-based starting crop separately for each selected device's aspect ratio.
- [x] Choosing an anchor positions every selected device's crop at that corner or the center of the source, within image bounds.
- [x] The active global method and anchor are visibly identifiable; no per-device method selector is offered.
- [x] Each device editor displays the source image and its crop boundary and supports dragging the crop without moving other devices' crops.
- [x] Dragging preserves aspect ratio and crop size and clamps the rectangle to the source boundaries; pointer interaction supports mouse and touch.
- [x] Each device has Reset position, which restores that device to the current global method's calculated position without changing other devices.
- [x] Changing the global method or anchor discards all manual positions and recalculates the selected devices' crops. Newly selected devices start from the active global method.
- [x] Exported framing matches the final crop shown for each device, including manual adjustments.

## Feature: Live OLEDify adjustment

Provide an OLEDify enable control and an integer threshold from 0 to 255, disabled by default. When enabled, pixels whose largest RGB channel is less than or equal to the threshold become RGB (0, 0, 0); other pixels are unchanged by this operation. This is a hard cutoff, without a gradual shadow fade.

### Acceptance criteria

- [x] The control explains that OLEDify turns near-black colors into true black and displays the selected threshold.
- [x] Enabling, disabling, or changing the threshold updates the main source preview and every selected device preview without a separate Apply action.
- [x] Pixels at the threshold are blackened and pixels above it retain their RGB values from before the OLEDify operation.
- [x] Disabling OLEDify restores the untreated image appearance without losing crop positions; threshold changes also preserve crop positions.
- [x] Final PNGs apply the same setting and cutoff rule as previews. OLEDify is applied after resizing so resampling does not reintroduce near-black values into pixels that the final cutoff should make pure black.
- [x] Rapid changes settle on the latest settings; older processing responses cannot replace newer previews or downloads.

## Feature: Named previews and downloads

The Download page provides an editable base name, a preview and individual download for each selected device, and Download all as a ZIP. Export lossless PNG regardless of input format. Initialize the name from the source filename without its extension, or `wallpaper` for clipboard images without a filename.

### Acceptance criteria

- [x] Download displays only the selected device outputs, reflecting the current crop positions and OLEDify settings.
- [x] Editing the base name updates the displayed download names. Unsafe filename characters and path components are normalized to a safe nonempty basename, with `wallpaper` as the fallback.
- [x] Individual downloads use `<name>-<device-id>.png`; the archive uses `<name>.zip` and contains the same named PNGs at its root.
- [x] The ZIP contains exactly one PNG per selected device, with image contents matching the individual downloads.
- [x] No AI name-suggestion control or AI-generated name appears in this version.
- [x] Processing and download-generation progress is visible. Failures show a clear error and permit retry without requiring a new upload.
- [x] Downloads cannot silently serve stale results after settings change or serve incomplete files while generation is pending.

## Feature: Navigation, temporary jobs, and remembered preferences

Provide the three pages from the mockup, Back from Download to Processing, and Start over to return to Input. Jobs are temporary: source images, manual crop positions, generated images, and the edited job name are not restored after a browser reload or application restart. Remember device selections, the global crop method and anchor, and OLEDify enable/threshold preferences between wallpapers.

Persist preferences only as flat files, under `/data` in Docker. Document the data mount and non-root write-permission requirements. Runtime configuration remains validated static JSON, including any new resource or temporary-storage settings.

- [x] The complete Input → Processing → Download workflow works in development and in the production container through the existing single server port.
- [x] Back from Download preserves the source, device selections, crop method, manual positions, OLEDify settings, and edited name; returning to Download reflects subsequent changes.
- [x] Start over clears the current source, name, manual crop positions, and generated outputs, while retaining preferences for the next wallpaper.
- [x] Reloading the browser or restarting the application begins at Input without restoring the previous job; saved preferences survive when the persistent data directory is retained.
- [x] Temporary files and other job resources are reclaimed when jobs are discarded or expire, including abandoned jobs; cleanup behavior is documented and storage does not grow indefinitely from repeated use.
- [x] The application requires no accounts, database, external AI service, or additional container. Processing remains local to the deployment.
- [x] The interface remains usable on desktop and narrow mobile screens, with labeled controls, keyboard-operable standard controls, visible focus, and understandable validation messages.
- [x] Preference-storage errors are reported clearly. Documented configuration defaults, startup validation, `/config/config.json` replacement behavior, and single-image non-root Linux amd64/arm64 deployment remain supported.
- [x] Automated checks cover upload validation, exact dimensions, crop anchors and bounds, entropy cropping, OLEDify cutoff boundaries, naming, ZIP contents, and preference persistence through appropriate server injection and Lit browser tests.
