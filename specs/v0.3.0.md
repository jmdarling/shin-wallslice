# v0.3.0 — Device folders in downloads

Status: implemented

Add an optional folder layout for ZIP downloads so users can organize wallpapers by device. Preserve the existing filename layout by default and remember the user's choice.

## Feature: Organize ZIP outputs into device folders

The Download page provides an “Organize into device folders” checkbox. When checked, Download all places each selected device's PNG in a folder named with that device's stable ID, using the wallpaper's base name without a device suffix. Folders follow device IDs even when multiple devices share the same pixel dimensions.

### Acceptance criteria

- [x] The Download page offers a labeled, keyboard-operable “Organize into device folders” checkbox that is unchecked on first use.
- [x] With the checkbox unchecked, Download all produces `<name>.zip` with `<name>-<device-id>.png` entries at the archive root, preserving the current behavior.
- [x] With the checkbox checked, Download all produces `<name>.zip` with entries at `<device-id>/<name>.png`. For example, the iPhone 18 Pro Max output for a wallpaper named `sunset` is stored at `iphone-18-pro-max/sunset.png`.
- [x] Each selected device receives its own folder in folder mode, including devices that share pixel dimensions. The ZIP contains exactly one PNG per selected device and no PNGs for unselected devices.
- [x] Both layouts use the current safely normalized wallpaper base name, including the existing `wallpaper` fallback for an empty or unusable name. ZIP entries remain within their intended archive paths.
- [x] Changing the checkbox changes the next ZIP's layout without losing the edited name, crop positions, or OLEDify settings. The PNG contents match the current generated outputs in either layout.
- [x] Individual PNG downloads retain `<name>-<device-id>.png` filenames regardless of the checkbox setting.
- [x] The checkbox choice survives navigation back to Processing and returning to Download, Start over and a new wallpaper, browser reloads, and application restarts when the persistent data directory is retained. Store this preference with the existing flat-file preferences under `/data` in Docker; existing installations without the preference default to unchecked.
