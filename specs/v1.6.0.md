# v1.6.0 — Choose devices before uploading

Status: implemented

Make the Processing page's device selection available on Input so users can choose
their outputs before finding or uploading an image. Show recommended source
wallpaper dimensions that update immediately with the selected devices.

## Feature: Shared device selection on Input and Processing

Input offers the same output-device choices as Processing. Both pages use the
same selection and retain the existing defaults and preference behavior.

### Acceptance criteria

- [x] Input lists the same catalog devices, display names, and individual selection controls as Processing. All existing presets remain available on both pages; catalog additions appear on both without separate lists to maintain.
- [x] On first use, Input preselects only iPhone 18 Pro Max and M5 iPad Pro 11-inch. When saved preferences exist, Input initializes from the remembered device selection, following the existing preference-loading and error behavior.
- [x] Selecting or deselecting a device on Input updates the current selection and saves it through the existing preference mechanism. After a successful file-picker, drag-and-drop, or clipboard upload, Processing shows exactly that selection and creates previews for those devices, without reverting to defaults or an earlier saved selection.
- [x] Changes on Processing remain reflected when returning to Input through Start over and when beginning another wallpaper. Successful preference saves from either page survive reload and application restart. Start over retains device choices while clearing the previous image as it does today.
- [x] An empty selection is allowed and remembered. Input still accepts an image with no devices selected; Processing continues to require at least one selected device before proceeding to Download. Selecting devices on Processing retains the existing crop initialization and rendering behavior.
- [x] Device controls remain usable with keyboard, pointer, and touch, have accessible labels and checked states, and fit desktop and narrow mobile layouts in light and dark appearances. Existing upload controls remain accessible alongside the new choices.

## Feature: Live recommended source dimensions

On Input, display recommended source wallpaper dimensions in pixels as width ×
height. Compute width as the largest output width among selected devices and
height as the largest output height among selected devices, even when those
maxima come from different devices. Use the catalog's actual output dimensions,
including square tablet outputs, without rotating devices or substituting native
screen dimensions.

### Acceptance criteria

- [x] Once catalog and preferences have loaded, Input shows a clearly labeled recommended source size for the current selection before any image is uploaded. The presentation identifies width × height and pixel units.
- [x] Selecting or deselecting a device updates the recommendation immediately, without an Apply action, page navigation, upload, or waiting for a preference-save response. Rapid changes settle on the current selection, and removing the device responsible for either maximum recalculates that dimension.
- [x] The default phone and 11-inch tablet selection recommends **2420 × 2868 px**. All six current presets recommend **3840 × 2868 px**. A single selected device recommends its own exact output dimensions; for example, the 11-inch tablet alone recommends **2420 × 2420 px** and Generic 16:9 4K alone recommends **3840 × 2160 px**.
- [x] With no devices selected, show “Select at least one device to see recommended dimensions” instead of a numeric recommendation. During initial loading or a catalog-load failure, do not display a fabricated size, an empty-selection recommendation before preferences are known, or `0 × 0`.
- [x] The dimensions are guidance for choosing a source image. They do not impose a new upload-size or aspect-ratio requirement, resize the source, or change output sizes. Existing image-validation/resource limits, per-device upscaling warnings, and permission to use smaller source images remain in effect.
- [x] The recommendation and empty-selection prompt remain readable on desktop and narrow mobile layouts in both appearances. Assistive technology can identify the dimensions and receive polite updates without moving focus away from device controls.
