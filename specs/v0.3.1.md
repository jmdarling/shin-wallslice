# v0.3.1 — OLEDify threshold loading toast

Status: implemented

Make processing visible when users change the threshold while OLEDify is enabled.

## Feature: Loading toast for OLEDify threshold changes

Show a loading toast when a user changes the threshold while OLEDify is enabled. Keep the toast visible until processing for the latest threshold finishes, including when the user makes several adjustments in quick succession. This change is scoped to threshold adjustments; toggling OLEDify does not itself trigger this toast.

### Acceptance criteria

- [x] Changing the threshold while OLEDify is enabled immediately shows a loading toast with a visible loading indicator and text explaining that OLEDify processing is underway, without requiring a separate Apply action.
- [x] The toast remains visible while the latest threshold update is pending or processing and disappears when its updated previews and generated outputs are ready.
- [x] Rapid threshold adjustments use a single loading toast that remains visible until the latest update finishes; an older processing response cannot dismiss it prematurely or replace the latest results.
- [x] If processing for the latest threshold fails, the loading toast clears and the existing clear error and Retry behavior remains available.
- [x] The toast is visible on desktop and narrow mobile screens without blocking threshold adjustments, and its processing message is exposed as an accessible status announcement.
- [x] Threshold adjustments continue to preserve crop positions and update the main source preview, selected device previews, and generated outputs using the latest setting.
