# v0.8.0 — AI subject detection

Status: implemented

Use the configured vision service to identify an image's main subject and frame device crops around it. Retain local Sharp entropy cropping as an explicit choice and as a fallback, keeping AI optional.

## Feature: AI and entropy crop choices

When AI is enabled, Processing offers separate Smart (AI) and Smart (entropy) choices alongside the existing spatial anchor selector. Reuse the existing server-side OpenAI-compatible connection and configuration, including support for compatible endpoints without bearer authentication; no new provider settings are needed.

### Acceptance criteria

- [x] With AI enabled, users can select Smart with an “(AI)” subtitle, Smart with an “(entropy)” subtitle, or any of the existing five anchors. These choices are mutually exclusive, with a clear selected state and accessible names that distinguish both Smart methods.
- [x] With AI disabled, entropy and anchors remain fully usable and no AI requests are made. The AI choice is unavailable, and a saved AI preference resolves to entropy without preventing the workflow.
- [x] On first use, the default is AI when enabled and entropy otherwise. Existing saved Smart preferences resolve to AI when enabled and entropy otherwise; existing anchor preferences retain their anchor selection.
- [x] After migration, explicit AI, entropy, and anchor choices are remembered across navigation, Start over, new images, reloads, and application restarts with persistent data retained. An explicit entropy preference continues to select entropy when AI is enabled.
- [x] Both Smart methods and all anchors support pointer, touch, and keyboard selection with visible focus and selection distinguishable without color alone. The controls remain usable without overlap or horizontal overflow on desktop and narrow mobile screens in light and dark modes, following the existing Web Awesome visual design.

## Feature: Subject-aware device framing

Analyze the full oriented source image before cropping or OLEDify. Identify bounds around the main subject, treating a coherent group as the subject when appropriate. Derive each device's starting crop from those bounds, preserving as much of the subject as the device aspect ratio allows. Detection is best effort and does not guarantee perfect recognition or framing for every image.

### Acceptance criteria

- [x] Each accepted upload automatically starts one subject-detection task when AI is enabled, including file selection, drag-and-drop, and clipboard input, regardless of the selected crop method. Rejected uploads start none.
- [x] Detection uses the configured vision model and a bounded representation of the full oriented source. Image preparation and requests have documented size and time bounds and respect the application's existing resource safeguards. Credentials and upstream error bodies are not exposed to the browser, logs, or user-facing errors.
- [x] The detection prompt requests subject bounds and an optional focal region within them, permits a coherent subject group, and allows an explicit no-clear-subject result for images such as abstract patterns. Text within an image is treated as content rather than instructions to change the task.
- [x] Returned bounds are validated before use and mapped correctly from the analyzed representation to the oriented source. Malformed, empty, refused, nonfinite, inverted, out-of-range, or focal-outside-subject bounds are treated as detection failures rather than producing unsafe crop coordinates.
- [x] Every AI crop retains the existing fixed crop size and device aspect ratio and remains entirely within the source. When the subject fits, the crop contains its full bounds; when it cannot fit, positioning prioritizes a detected focal region (such as the face/head for a person), preserving as much of the remaining subject as possible within the source limits. Without a clear focal region, use the subject's center. Preserve the entire subject or coherent group whenever it fits.
- [x] A coherent group can be framed together rather than arbitrarily selecting one member. A valid no-clear-subject result uses the existing per-device entropy crops and displays an understandable explanation without presenting it as a service failure.
- [x] Successful detection is reused for all device shapes in the current job. Selecting devices, changing methods, resetting positions, navigating, changing OLEDify, or downloading does not trigger another detection request.
- [x] Smart (entropy) continues to use the existing Sharp entropy strategy separately for each device. Anchors, output dimensions, upscaling warnings, OLEDify, and download formats retain their current behavior.

## Feature: Nonblocking detection and manual control

Show entropy previews while detection is pending. Apply a successful result to untouched crops only while AI is the active method. Preserve manual positioning and allow users to continue processing and downloading throughout detection.

### Acceptance criteria

- [x] Processing opens without waiting for the vision service. When AI is selected, an accessible pending indication explains that current previews use entropy until detection completes; navigation, manual positioning, name editing, and downloads remain usable.
- [x] A result arriving while AI is active updates only selected-device crops that have not been manually positioned since their latest initialization or reset. It does not overwrite a manual edit, even if that edit returned the crop to its original position.
- [x] A result arriving while entropy or an anchor is active does not alter current crops. Selecting AI later applies the available AI crops using the existing global method-change behavior.
- [x] Explicitly changing the global crop method or anchor resets selected-device positions as before. Selecting AI after successful detection uses its calculated crops; while detection is pending, failed, or has no clear subject, it uses entropy crops with the corresponding status.
- [x] Manual dragging remains independent per device. Reset position restores only that device using the active method's available result; a reset to AI while pending makes that crop eligible for the later AI result. Newly selected devices initialize from the active method.
- [x] Any applied crop change invalidates stale previews and downloads until matching outputs are ready, preserving the existing guarantee that exported framing matches the current previews. Downloads already initiated retain the framing current when initiated.

## Feature: Fallback, recovery, and verification

Service failures fall back to entropy with a visible nonblocking message and explicit Retry. Detection and AI naming remain independent tasks: failure or retry of one does not fail or restart the other.

### Acceptance criteria

- [x] Timeouts, connection errors, authentication failures, rate limits, unsupported vision input, preparation failures, and invalid detection responses settle the pending state, retain manual edits, and use entropy for otherwise eligible AI crops. A visible message explains the fallback and offers Retry without requiring another upload.
- [x] Fallback does not silently change the saved crop preference to entropy. The interface distinguishes AI success, pending entropy previews, no-clear-subject entropy fallback, and service-failure entropy fallback.
- [x] Retry starts another detection attempt for the current image without duplicating concurrent attempts or restarting naming. There is no automatic retry loop. A successful retry observes the same active-method and manual-edit protections as the initial result.
- [x] AI naming retains its existing automatic behavior and name-edit protections. Naming and detection can succeed or fail independently, and neither blocks local processing or downloads.
- [x] Starting over, replacing an image, deleting or expiring a job, reloading, or restarting prevents outstanding results from changing a later workflow. Abandoned AI work is cancelled or bounded; detection results share the temporary-job lifecycle and are not persisted across reloads or restarts.
- [x] Documentation explains both crop methods, defaults and preference migration, automatic image submission through the existing AI configuration, pending behavior, subject-group framing, fallback, Retry, and the best-effort nature of detection.
- [x] Controlled server tests cover enabled and disabled AI, request authentication, valid and invalid bounds, orientation and coordinate mapping, subject containment and partial preservation across device shapes, group and no-subject responses, failure and Retry, task independence, request reuse, and stale-job cleanup. Prompt and response fixtures verify detection instructions without requiring live credentials or asserting guaranteed model recognition.
- [x] Lit Chromium browser tests cover method selection and preference migration, pending previews, successful updates, manual edits before late results, switching away from AI, Reset position, new device selection, Download navigation, fallback and Retry, and preview/export consistency. Visual verification covers desktop and narrow mobile layouts in both themes.
- [x] Root lint, formatting checks, explicit TypeScript checks, tests, and production builds pass. The application retains its single-container, non-root Node.js 24 deployment on Linux amd64 and arm64, flat-file persistence, and local operation with AI disabled.

## Developer clarification

The developer approved prioritizing a detected focal region when the full subject cannot fit, after a phone crop cut through a character's face while the wider iPad crop framed it well. Full-subject/group preservation remains the priority whenever it fits.

The developer requested that progress toasts appear only while work is running, with persistent messages reserved for errors. Successful detection removes its banner. A no-clear-subject result is explained as an inline crop-method note instead of a persistent toast.

The developer requested stronger focal-selection instructions after a narrow crop favored a held sword. For prominent people/characters, detect the person as the subject and prioritize the visible face/head over held equipment or nearby props. Object-focused images can still use the object as the subject.
