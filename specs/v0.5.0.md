# v0.5.0 — AI wallpaper naming

Status: implemented

Optionally suggest a short wallpaper name from the source image using a configured OpenAI-compatible vision service. Establish a reusable server-side AI connection for future vision features while limiting this version's AI functionality to wallpaper naming.

## Feature: Optional AI connection

Configure the connection through the existing static JSON runtime configuration, including an API base URL, model identifier, and optional bearer token. Support OpenAI and compatible hosted or self-hosted services implementing image input through Chat Completions; compatibility does not imply support for every provider-specific API. No in-app connection settings are introduced.

### Acceptance criteria

- [x] AI is disabled in shipped defaults. Existing configuration files without AI settings remain valid and retain the current local workflow without contacting an AI service.
- [x] Enabling AI requires a valid HTTP(S) API base URL and a nonempty model identifier. A supplied token is used for bearer authentication; omitting it supports endpoints that do not require authentication. Local HTTP endpoints are supported for self-hosted deployments.
- [x] Invalid AI configuration produces a clear startup configuration error without disclosing the token. An unreachable service or incompatible model does not prevent application startup or use of local wallpaper processing.
- [x] Documentation explains the JSON settings, base URL semantics, restart requirement, vision-capable model requirement, and read-only `/config/config.json` deployment. It states that enabling AI automatically sends an image representation to the configured service after upload.
- [x] AI requests originate from the server. Tokens are never sent to the browser or included in client assets, logs, or user-facing errors; upstream error bodies are not exposed verbatim.
- [x] Connection configuration, authentication, request lifecycle, and error handling are reusable independently of the wallpaper-naming prompt. Future AI tasks can reuse the connection without duplicating provider transport or credentials; this version adds no AI cropping, tagging, chat, provider-management interface, or other vision feature.

## Feature: Automatic concise name suggestions

After a source image is accepted, request one name suggestion automatically while the user continues through Processing and Download. Use the full source composition before device cropping or OLEDify, with orientation respected and a bounded, resized representation suitable for naming. The existing Download-page name field remains editable.

Suggestions use lowercase kebab-case, ideally around three meaningful words. Include a recognizable show or game title when the model can identify it; additional words are appropriate when they add meaning or preserve the title. Recognition is best effort, and uncertain images receive descriptive names rather than invented franchise attribution.

### Acceptance criteria

- [x] With AI enabled, each accepted image triggers one automatic naming request using image content and the configured model, including images supplied through file selection, drag-and-drop, or clipboard paste. Rejected uploads trigger none.
- [x] Naming uses the oriented source image, independently of device selections, manual crop positions, and OLEDify settings. Image preparation has documented size bounds and remains within the application's existing resource safeguards.
- [x] The naming prompt requests one concise, descriptive name, aims for roughly three words, permits more only when meaningful, and requests recognizable show or game titles without guessing uncertain identities. Image text is treated as image content rather than instructions to change the task.
- [x] An accepted suggestion is normalized to a safe, nonempty lowercase kebab-case basename, without an extension, path components, explanatory prose, or surrounding formatting. Existing filename length and path-safety protections continue to apply. Empty, refused, malformed, or unusable responses are treated as naming failures.
- [x] A successful suggestion replaces the source-filename default, or the `wallpaper` clipboard fallback, unless the user has edited the name. The Download page identifies an automatically supplied name as AI suggested and allows the user to override it through the existing field. Completed-suggestion attribution uses a small sparkle icon with an accessible “AI Powered” label beside that field on Download, with no success banner on Processing or Download; pending and failure statuses remain visible with Retry after failure.
- [x] An AI result arriving after any user edit does not overwrite that edit, even if the user cleared the field or changed it back to the original default. Retry also respects this protection.
- [x] The current name is used consistently for displayed filenames, individual PNGs, ZIP names, and both ZIP organization layouts. Back navigation and changes to crop, device, OLEDify, or folder settings preserve the name and do not trigger another AI request.

## Feature: Nonblocking naming and recovery

Keep local image processing and downloads available while naming is pending or unavailable. Until a suggestion is applied, retain the existing source-filename default or clipboard fallback. Provide visible naming status and an explicit Retry action after failure without requiring another upload.

### Acceptance criteria

- [x] Pending naming has an accessible status indication without blocking Processing, navigation to Download, name editing, or downloads. A download initiated before naming completes uses the name current at that moment.
- [x] Timeouts, connection errors, authentication failures, rate limits, unsupported vision input, and invalid responses clear the pending state, preserve the current name and image workflow, and show an understandable nonblocking failure message with Retry.
- [x] Requests have documented finite time and response-size bounds. There is no automatic retry loop; Retry explicitly requests another suggestion for the current image and cannot create duplicate concurrent naming requests for that image.
- [x] Starting over, replacing the image, discarding or expiring its job, or leaving through a browser reload prevents outstanding results from changing a later workflow. AI work is cancelled or bounded so abandoned requests do not accumulate indefinitely. Suggestions share the existing temporary-job lifecycle and are not restored after reload or restart.
- [x] Automated server and Lit browser tests cover disabled configuration, enabled requests and authentication, safe normalization, successful defaulting, edits before a late result, failure and Retry, stale results after Start over or a new image, and unchanged download naming rules. Tests use controlled AI responses and require no live service or credentials; prompt and representative response fixtures verify the naming instructions without asserting guaranteed visual recognition.
- [x] Root lint, formatting checks, explicit TypeScript checks, tests, and production builds pass. The existing single-container, non-root Linux amd64/arm64 deployment remains supported, with AI optional and no new database or companion-container requirement.
