# shin-wallslice 1.1.0 — A considered visual identity

The Passepartout design puts wallpapers in quiet image mats, gives controls a
consistent violet palette, and clearly marks Input, Processing, and Download.
Processing and Download lose the repeated promotional headings and explanations.
The primary archive action is now **Download ZIP**, and OLEDify's checkbox is
**True black shadows**. Browser-driven light/dark appearance and reduced-motion
feedback follow the same identity.

The workflow and output behavior are preserved: file/drop/paste input, device
presets, entropy and optional AI framing, all five anchors, independent manual
crop positions, OLEDify, naming, device folders, and individual PNG/ZIP downloads.
README screenshots and usage labels now match the app. The developer selected
Passepartout from three proposals and explicitly signed off on the running app.

Install/update: [README](https://github.com/jmdarling/shin-wallslice#get-started)
and [Unraid guide](https://github.com/jmdarling/shin-wallslice/blob/main/docs/unraid.md).
Image: `ghcr.io/jmdarling/shin-wallslice:1.1.0`, with aliases `:1`, `:1.1`, and
`:latest`. The `:1.0` series and exact older releases are preserved.

Compatibility: no configuration or preferences migration. Keep the same `/data`
mount, port mappings, private configuration, and optional AI settings. Node.js 24,
non-root runtime, Linux amd64/arm64, and the existing memory/storage requirements
are unchanged. The release does not update running installations automatically.

Validation: local source checks passed, including 100 server tests and 62 Chromium
component tests. Real-image browser verification checked exact PNG dimensions and
framing pixels, OLEDify cutoff and alpha, both ZIP layouts, navigation, disposal,
and preference persistence. All three screens were checked in light/dark at
1440px, 390px, and 320px. AI states/recovery use controlled browser responses;
no live external AI provider was exercised.

Published multi-platform digest:
`sha256:bd834e9e485e3ca43180da77899fe6ca2a10e080635d8ab5398d238c101bbd10`.
Tags `:1.1.0`, `:1`, `:1.1`, and `:latest` all resolve to this artifact.
Both runtime architectures carry SPDX SBOM and SLSA provenance attestations.
The exact `1.0.1` artifact and `:1.0` alias remain unchanged.

Publication verification: [Release run 39633885386](https://github.com/jmdarling/shin-wallslice/actions/runs/39633885386)
passed source checks, native amd64/arm64 candidate smoke and persistence tests,

1 UNKNOWN** package/advisory instances. The HIGH findings represent the same eight

[base-system applicability review](vulnerabilities.md). No Node-package findings
or fixable HIGH/CRITICAL findings were reported. This is not a zero-finding scan.
The [GitHub Release](https://github.com/jmdarling/shin-wallslice/releases/tag/v1.1.0)
retains the complete reports, smoke logs, manifest, independent registry check,

Rollback: download active outputs and back up preferences/private configuration.
Choose the exact `1.0.1` image or its recorded digest and recreate with the same
mounts/settings. No preference conversion is needed. Temporary jobs do not survive
container replacement; original images and already downloaded outputs are yours
to retain. See [release operations](releases.md) for artifact inspection/recovery.
