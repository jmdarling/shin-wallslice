# shin-wallslice 1.7.0 — Unified activity dock

Upload, rendering, AI, preference, download, and server-save notifications now
share one activity dock across Input, Processing, and Download. The dock stays
collapsed until you explicitly expand it. A spinner and active count indicate
work; errors and required decisions update the attention count without opening
anything automatically.

Each task updates in place. Expand the dock for results, specific retry actions,
and saved/not-saved file details. Existing-file replacement still requires an
explicit Replace or Cancel decision. Dismissal does not resolve errors, and
Show dismissed activity restores them. Start over clears wallpaper history while
retaining unresolved application-wide errors. Reload clears notification history.

## Install, update, and roll back

Image: `ghcr.io/jmdarling/shin-wallslice:1.7.0`, with aliases `:1`, `:1.7`, and
`:latest` after successful publication. Follow the [README](../../README.md) or
[Unraid guide](../unraid.md), retaining existing data and output mounts.
Publishing a release does not update installations automatically.

No new configuration, storage, or preference migration is required. Notification
history exists only in browser memory. Rollback to
`ghcr.io/jmdarling/shin-wallslice:1.6.0` restores the earlier notification layout
without changing stored preferences or output files.

The runtime remains Node.js 24, non-root, one container/process/port, with Linux
amd64 and arm64 support. AI remains optional and disabled by default.

## Verification and limits

The developer tried the revised app and signed off. Local `pnpm check` passed
lint, formatting, strict TypeScript checks, 139 server tests, 98 Chromium tests,
production builds, and distribution checks. [Verification notes and captures](../design/v1.7.0/README.md)
cover real uploads, rendering, ZIP handoff, server saving, conflict review,
preference-error recovery, and desktop/mobile light/dark layouts.

No live external AI, human screen-reader, physical-mobile, or fresh Unraid hardware
session was performed. Controlled Chromium tests cover AI concurrency and failures.

The release workflow verifies native amd64/arm64 containers, scans candidates,
and checks anonymous access before promoting aliases. Exact digest and scan
findings will be recorded from its evidence; a passing gate does not imply zero
vulnerability findings.
