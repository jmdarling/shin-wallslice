# v1.3.0 — Automatic OLEDify recommendations

Status: implemented

Automatically choose per-image OLEDify defaults using a local near-black pixel check. When AI is enabled, refine eligible images with a bounded vision-guided binary search for the highest cutoff judged to preserve the image without material detail loss or visible artifacts.

## Feature: Local OLEDify candidate detection

Analyze each accepted, oriented source image locally before OLEDify. Use its percentage of black or near-black pixels to automatically check or uncheck OLEDify for that image, including on installations without AI.

### Acceptance criteria

- [x] By default, an image is a candidate when at least 15% of its pixels have all three RGB channels at or below 32 in the normalized sRGB source. Both comparisons are inclusive. Evaluate the full source independently of selected devices and crop positions; fully transparent pixels must not falsely inflate the dark-pixel percentage.
- [x] Provide separate runtime settings for the minimum qualifying percentage and near-black cutoff, defaulting to 15% and 32. Document the percentage units; validate a finite percentage from 0 through 100 and an integer cutoff from 0 through 255. Support partial JSON and corresponding `SHIN_WALLSLICE_` overrides under the existing precedence and startup-validation rules, including read-only JSON and credential-safe errors.
- [x] Every accepted new image receives fresh automatic defaults: OLEDify on at cutoff 16 for a candidate, and off with cutoff 16 for a noncandidate. Previously saved OLEDify enable/cutoff values do not override these per-image defaults. Other saved preferences retain their behavior.
- [x] Candidate detection is deterministic, needs no model or network request, and remains available with AI disabled or unavailable. Rejected uploads do not start analysis. Analysis respects existing image and resource safeguards and does not change source pixels.
- [x] Boundary fixtures demonstrate the inclusive channel cutoff and percentage threshold, distinguish a pixel with one channel above the cutoff, and cover all-black, bright, mixed, and transparent images. An analysis failure is reported without blocking manual OLEDify controls or the ordinary workflow, and does not silently claim a successful recommendation.

## Feature: Vision-guided cutoff search

For local candidates only, automatically use the configured vision service to compare the original composition with actual OLEDified trial previews. Search adaptively in binary-search style rather than asking the model to guess a cutoff from the original alone. Retain the existing deterministic pixel transformation; this feature does not generate or repaint image content.

### Acceptance criteria

- [x] AI-disabled installations make no vision requests. With AI enabled, each accepted candidate starts one automatic search; noncandidates skip this task and retain OLEDify off. Existing naming and subject detection continue independently.
- [x] Search the existing integer cutoff range of 0 through 255. Each vision evaluation compares the unmodified original composition with a clearly identified trial at a known cutoff and judges material image changes, lost shadow detail, banding, hard edges, and other visible artifacts. Include an explicit unacceptable/acceptable result and validate responses before using them.
- [x] Choose subsequent trial cutoffs adaptively: an acceptable trial raises the lower search bound and an unacceptable trial lowers the upper bound. Retain the highest actually evaluated acceptable cutoff; never return an unevaluated higher cutoff. If no trial that turns additional pixels black is judged acceptable, recommend OLEDify off rather than forcing a destructive conversion.
- [x] Provide a configurable maximum of vision requests per search, defaulting to 8. Validate and document the supported finite positive integer range and corresponding JSON/environment settings. Stop when the search converges or the request limit is reached, with no automatic retry loop. Explicit Retry starts a new bounded attempt.
- [x] Trial comparisons use the full oriented source composition and the actual inclusive all-RGB-channels OLEDify rule. Preserve dark pixel values in analysis preparation: do not blindly reuse the existing lossy naming JPEG if its compression or transparency treatment changes the shadows being judged. Document bounded image dimensions/bytes, comparison preparation, per-request timeout, and total search limits. Keep comparisons within existing resource protections.
- [x] Reuse the existing server-side AI connection, endpoint/model configuration, authentication, and safe error handling. Support the required original/trial comparison through the configured OpenAI-compatible vision service; unsupported image comparison, malformed or out-of-range judgments, timeout, authentication, rate-limit, and connection failures produce a nonblocking failure with Retry.
- [x] Apply a successful recommendation as one shared OLEDify enable/cutoff choice across all selected device outputs. Device selection, crop movement, navigation, and ordinary rendering do not restart the source-level search. Reuse completed recommendations within the job.
- [x] The model's judgment is best effort, not a guarantee of a globally optimal cutoff or artifact-free output. Verify representative dark-background artwork, photography with subtle shadow detail or gradients, and images with hard dark edges. Record the original, evaluated cutoffs, resulting recommendation, and visual review findings without exposing credentials. Deterministic provider fixtures verify search decisions and bounds; live visual evaluation is distinguished from mocked transport checks.

## Feature: Immediate defaults and protected manual control

Keep local previews and exports usable while vision analysis runs. Users retain the existing OLEDify switch and threshold control and can override automatic choices at any time.

### Acceptance criteria

- [x] Local candidates immediately use OLEDify on at cutoff 16 while AI is pending. Noncandidates remain off. Users can continue through Processing and Download, including PNG/ZIP download and configured server saving, without waiting for AI.
- [x] Show accessible pending, completed, skipped/not-recommended, and failed feedback near OLEDify as relevant. Explain the local recommendation and distinguish it from an AI-refined result, including the selected cutoff or recommendation to leave OLEDify off. Failure feedback offers Retry and preserves the usable local result rather than applying an incomplete search.
- [x] Changing either OLEDify enablement or cutoff marks both settings as manually controlled for the current image. Late analysis results and retries never overwrite those manual settings, even if the user restores the original value. Completed recommendations remain visible without being silently reapplied.
- [x] Back navigation, crop changes, device changes, and rerenders preserve the current image's manual choices. A new accepted image resets that protection and receives fresh automatic defaults. Start over, replacement, job expiry, and shutdown cancel or invalidate pending searches so stale results cannot affect another workflow.
- [x] Applying an automatic result updates previews through the existing render lifecycle. Superseded renders cannot become current or enable stale exports; PNGs, ZIPs, and server-saved files match the current completed previews. A previously completed export remains the output of its own accepted settings and is not silently rewritten when a later recommendation arrives.
- [x] OLEDify continues to set RGB to true black only when every RGB channel is at or below the selected cutoff, after output resizing, preserving alpha and all other RGB pixels. Automatic recommendations do not alter crop positions, naming, or unrelated preferences.
- [x] Controls and feedback work with keyboard and assistive technology on desktop and narrow mobile layouts in light and dark appearances.

### Developer clarification

The developer requested lowering the default minimum qualifying near-black
percentage from 20% to **15%**. The inclusive RGB cutoff remains **32** and the
immediate OLEDify fallback cutoff remains **16**. The default-boundary fixture
now verifies exactly 15% qualifies and a percentage below 15% does not.
`pnpm check` passed again after this change (130 server tests, 74 Chromium tests).

The developer also requested clearer UI wording for cutoff 16: describe it as the
local fallback while AI is pending, disabled, or failed. A successful result shows
the AI recommendation without repeating cutoff 16 as another recommendation.

The wording revision passed `pnpm check`, including 130 server tests and 74
Chromium tests. The 15% candidate rule and cutoff values are unchanged.
